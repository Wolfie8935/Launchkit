Why hoard

Built for teams who ship fast and sleep well

Three principles, no compromises: safety by default, zero config to start, total control when you need it.

Reversible by default

Every generated migration ships with a tested rollback script. If a deploy goes sideways, one command undoes it cleanly — no manual SQL forensics.

Zero-downtime by design

hoard rewrites risky operations — column drops, type changes, index builds — into safe, non-locking multi-step plans automatically.

Works with your stack

Postgres, MySQL, and SQLite out of the box. Plugs into any ORM or none at all — hoard reads your schema, not your framework's opinions.

How it works

From schema change to production in three commands

01

Edit your schema

Change a model, add a column, whatever you'd normally do. hoard doesn't care how you define your schema.

02

Generate a plan

Run hoard plan to see a human-readable diff plus the exact SQL that will run, before anything touches your database.

03

Apply with confidence

Run hoard up. hoard applies changes in safe batches and keeps a rollback ready for the next 24 hours automatically.
